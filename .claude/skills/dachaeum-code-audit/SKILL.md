# 다채움 동의서 코드 검수

## 원칙
- 수정은 `src/`·`data/`에서 하고 `npm run build`로 `index.html`을 다시 만든다. `index.html`을 직접 고치지 않는다.
- 기능 추가·디자인 변경은 요청이 있을 때만. 검수는 오류 수정과 테스트 추가로 한정한다.
- 판단이 필요한 정책(가격·보관기간·삭제 범위 등)은 고치지 않고 "결정 필요"로 보고한다.
- **main 머지·병원 페이지 배포는 사용자가 명시적으로 요청할 때만.** 작업은 별도 브랜치에서.
- 실제 환자 정보·백업 파일을 저장소·테스트에 넣지 않는다 (테스트는 가짜 환자만).

## 고정 기준 (바꾸지 말 것 — `test/`가 지킴)
1. **최종 환불금액 = MAX(0, 실제 납부액 − 계약 총액 × 10% − 이용금액)**
   - 실제 납부액(`paid`) = 예약금 + 기납부 예약금 + 선결제권 사용분 + 잔금 결제. 계약 총액(`total`)은 별도 값.
   - 위약금은 계약 총액 기준 (예약금·납부액 기준 아님). 0원 미만은 0원, 추가 청구 없음.
2. **이용금액** = 항목별 *계약 당시* 1회 정상가 × 실제 이용 수량. 총액 ÷ 횟수, 결제금액 비례 배분 금지.
   - 흑자: 시작한 병변만 그 병변 금액 전액 (5등분 금지). 얼굴 점 CO₂: 병변별 입력 정상가 합.
   - 얼굴 전체 CO₂ 추가옵션: 1회 · 110,000원 (가격 데이터에 명시), 점 CO₂와 별도.
3. **정상가 누락은 0원으로 계산하지 않는다.**
   - 신규 계약: 1회 정상가 없는 구성은 직원 입력 후에만 서명 (`unitInput`).
   - 기존 계약: 이용 기록이 있으면 '정상가 확인 필요'로 환불 확정 차단. 보완은 `priceFixes`(금액·근거·일시)로 별도 기록, 원 계약 항목·서명 문서는 불변.
   - PGM-0037·0106 남성 턱밑라인 포함 제모는 근거 확인 전까지 '정상가 확인 필요' 유지 (추정 금지).
4. **서비스 단가**: 계약 당시 값(`svcPrices`) 사용. 없는 이전 계약에 현재 가격표 자동 적용 금지. 약처방 14일 미만 15,000 / 14일 이상 20,000.
5. **결제수단별 환불**: 원결제 초과 금지, 합계 = 최종 환불금액, 자동 배분 금지. 선결제권 잔액 복구·기납부 예약금은 별도 줄.
6. **상태**: 등록완료 / 환불완료 두 가지. 환불 정산서 서명 저장 = 환불완료. 새 상태 추가 금지. 작성 중 정산은 계약별 저장·복원.
7. **기록 보존**: 서명 문서·환불 기록·결제·이용기록 삭제 불가. 환자 삭제 기능 차단 유지.
8. **백업·복원**: `dachaeum.*` 자료만 대상, 비밀번호 암호화(PBKDF2-SHA256 → AES-GCM). 복원 전 검사, 기존 자료는 합치지 않고 확인 후 교체, 실패 시 롤백. 다른 앱(재고관리) 자료 불변.

## 절차
1. 브랜치 만들기: `git checkout -b claude/<작업명> main`
2. 수정: `src/app.dc.js`(화면 로직) · `src/markup.html`(마크업) · `src/refund.js`(환불) · `src/pricing.js`(금액·결제) · `src/catalog.js` · `data/programs.json`(가격표, `json.dumps(indent=2, ensure_ascii=False)` 형식 유지)
3. 빌드: `npm run build` (수정 없으면 `index.html`이 바이트 단위로 동일해야 함)
4. 테스트: `npm install` 후 `npm test`
   - 이 원격 환경: `NODE_PATH=$(npm root -g) npm test` (Chromium만 있음)
   - 오류 수정은 **수정 전 코드에서 실패하고 수정 후 통과하는 테스트**를 추가해 증명한다.
5. 영역별 점검 (해당되는 것만):
   - 계약 생성: 저장값(total·paid·items·svcPrices·unitInput)과 동의서 표시가 같은지, 이전 환자 입력값이 남지 않는지
   - 환불 정산: 계약 간 기록 분리, 작성 중 저장·복원, 표시값 = 계산값, 입력 범위(음수·상한·cap)
   - 결제·잔금: 결제 정보 수정 중 잔금 기록 차단, 결제내역·납부액 누적
   - 문구: 동의서·정산서·화면 문구가 고정 기준과 같은지
   - 가격 관리 override(`dachaeum.priceOverride`)가 서명된 계약 값을 바꾸지 않는지
   - Safari: 공유 시트는 탭 직후 동기 호출, lookbehind·`.at()`·`structuredClone` 등 미지원 문법 금지

## 보고 형식
- **수정 완료**: 파일 · 위치 · 이전 동작 · 수정 후
- **금액 확인 필요 / 결정 필요**: 근거 없는 금액·정책은 값을 넣지 않고 목록으로
- **테스트**: 통과 n / 실패 n (실패는 그대로 보고)
- **미검증**: 실제 iPad Safari·실제 병원 자료 등 확인하지 못한 항목. Chromium 통과를 Safari 검증으로 쓰지 않는다.
